# Engineering Method 0.3.1

Released 2026-11-13. A maintenance release: every skill is now held to the
published skill authoring limits by a test.

## Changes

- Syncs [Method Core](https://github.com/phense/method-core) revision `4300085`
  (70 files). It adds `tests/test_skill_authoring.py`, which checks each
  `skills/*/SKILL.md`: a name of at most 64 lowercase letters, digits and
  hyphens without a reserved word; a description of at most 1,024 characters in
  the third person without XML tags; portable frontmatter keys; a body under
  500 lines; forward slashes in links; and a contents list at the top of every
  reference file above 100 lines.
- Adds a contents list to `shared/policies/lifecycle-handoffs.md` and, through
  the core, to the Claude and Codex platform adapters.
- No skill name, description or behaviour changes. All 19 skills already met
  the name, description and length limits.

## Verification and limits

The complete Python suite passes 347 tests on macOS. `scripts/validate-plugin`
and `sync-core --check` pass. The committed-source package is built twice for
reproducibility.

The test proves that the limits are kept. It does not measure whether a host
selects a skill for a plainly worded request. One unscripted probe on Claude
Code during this work loaded `systematic-debugging` for a failing test without
being told to, and loaded no specification skill for a new cross-module
feature request; that single run is an observation, not a rate. The paid native
routing and lifecycle evaluations were not rerun; the evidence limits of
[0.3.0](0.3.0.md) remain.

The downloadable package is `engineering-method-0.3.1.zip`; verify it with the
attached `SHA256SUMS`.

```sh

```


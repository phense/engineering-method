# Engineering Method 0.3.0

Released 2026-11-13. This release splits the former single plugin into three
repositories. Engineering Method keeps the engineering lifecycles; writing and
documentation move to a separate plugin; shared support comes from a pinned core.

## Changes

- Moves documentation planning, authoring, review, didactic writing guidance and
  PDF delivery to [Writing Method](https://github.com/phense/writing-method).
  Those skills are no longer part of this plugin.
- Bundles host adapters, backlog and continuity tools, verification, review,
  worktree, delegation and playbook support from
  [Method Core](https://github.com/phense/method-core). Core is vendored source,
  not a third plugin. `method-core.lock.json` pins revision `087476c` with 69
  files, their hashes and executable modes; `python3 scripts/sync-core --check`
  verifies the copy offline.
- Ships 19 skills: 11 engineering lifecycle skills and 8 shared support skills.
  With both plugins installed, each exposes its own byte-identical copy of the
  shared skills; invoke the current method's copy once.
- Labels managed GitHub Issues with the bundling method's name and compares only
  the executable bit in the core mode check.
- Makes the test suite pass below a symlinked temporary directory, as on macOS.

## Breaking change

After updating from 0.2.1 or older, the documentation skills are absent until
Writing Method is installed. They are then invoked as `writing-method:<skill>`
instead of `engineering-method:<skill>`. The `engineering_method` Python import,
CLI wrapper names, project `.engineering-method/` state and work IDs are
unchanged.

## Verification and limits

The complete Python suite passes 341 tests on macOS with the default temporary
directory. `scripts/validate-plugin`, `claude plugin validate --strict`,
`sync-core --check`, Python compilation, shell syntax and whitespace checks pass.
The GitHub `verify` workflow passes on the released commit's parent merge. The
committed-source package is built twice for reproducibility.

Native installation was checked with Claude Code 2.1.323, Codex CLI 0.169.0 and
OpenCode 1.19.5, each alongside Writing Method 0.3.0. One bounded probe per host
on Codex and OpenCode loaded `systematic-debugging` from this plugin and
`writing-procedures` from Writing Method by their native skill mechanism. This
shows discovery and loading, not routing quality.

The paid native routing and lifecycle evaluations of the original release gate
(`scripts/release-check --release`) were not rerun for this release. Routing and
lifecycle claims retain the evidence limits documented for [0.2.0](0.2.0.md) and
in the [split record](../verification/EM-018-method-split.md). No Gemini adapter
is claimed. Other host versions and operating systems are not covered.

The downloadable package is `engineering-method-0.3.0.zip`; verify it with the
attached `SHA256SUMS`.

## Install or update

```sh
claude plugin marketplace update engineering-method
claude plugin update engineering-method@engineering-method
```

```sh
codex plugin remove engineering-method@engineering-method
codex plugin add engineering-method@engineering-method
```

For a GitHub marketplace in Codex, run `codex plugin marketplace upgrade
engineering-method` first. Restart the host session afterwards. See
[Installation and maintenance](../installation.md) for a fixed-tag install and
[OpenCode installation](../opencode.md) for the source-linked loader.
